## 1. The Big Picture (Yeh Project Kya Hai?)

Tum ek **"Simple Bank"** ka real-world backend bana rahe ho (jaise Google Pay, PayPal ya kisi bank ka server hota hai).

### Core Features:
1. **User Accounts**: Users register kar sakte hain with username aur encrypted password.
2. **Bank Accounts**: Ek user ke paas different currencies (`USD`, `EUR`, `CAD`) ke bank accounts ho sakte hain.
3. **Money Transfer**: Account A se Account B mein paise transfer karna.
4. **Data Integrity & Safety**: Paise hawa mein gayab na hon (ACID transactions), aur multiple parallel transfers hone par system deadlock na ho.
5. **Security**: Token-based authentication (JWT & PASETO) taaki sirf logged-in user hi apna account access kar sake.

## 3. Golang Basics Refresher (Beginner Friendly)

Agar tum Go ke basics bhool gaye ho, toh sirf yeh 5 rules yaad rakho:

### 1. Variables & Types
Go is strictly typed.
```go
var amount int64 = 100
currency := "USD" // ':=' shorthand hai declaration + assignment ke liye
```

### 2. Structs (Classes ki jagah)
Go mein `class` nahi hota, data ko group karne ke liye `struct` use karte hain:
```go
type Account struct {
    ID       int64  `json:"id"`
    Owner    string `json:"owner"`
    Balance  int64  `json:"balance"`
    Currency string `json:"currency"`
}
```
> **Note on Tags**: `` `json:"owner"` `` batata hai ki jab yeh struct JSON banega toh key ka naam `"owner"` hoga.

### 3. Methods (Functions attached to Structs)
Go mein function ko kisi struct se jodte hain using a **receiver**:
```go
// (server *Server) ek receiver hai. Iska matlab yeh function sirf Server instance par chalega.
func (server *Server) Start(address string) error {
    return server.router.Run(address)
}
```

### 4. Error Handling (No try/catch!)
Go mein `try / catch` nahi hota. Functions do cheezein return karte hain: `(result, error)`.
```go
user, err := server.store.CreateUser(ctx, arg)
if err != nil {
    // Agar error aaya toh yahan aao
    ctx.JSON(http.StatusInternalServerError, errorResponse(err))
    return
}
// Agar error nahi aaya toh user mil gaya!
ctx.JSON(http.StatusOK, user)
```

### 5. Interfaces (Contracts)
Interface batata hai ki *kya-kya functions hone chahiye*:
```go
type Maker interface {
    CreateToken(username string, duration time.Duration) (string, error)
    VerifyToken(token string) (*Payload, error)
}
```
Jo bhi struct (`JWTMaker` ya `PasetoMaker`) yeh dono functions implement karega, woh `Maker` ban jayega!

## 6. How Everything Works Together (An Example Flow)

Jab koi user `POST /transfers` request bhejta hai:
1. **Gin Router** ([`server.go`](file:///c:/Users/apoor/Desktop/golang/proj/api/server.go)): Request ko pakad kar [`createTransfer`](file:///c:/Users/apoor/Desktop/golang/proj/api/transfer.go) handler ko deta hai.
2. **Validator**: Check karta hai ki `FromAccountID != ToAccountID`, `Amount > 0`, aur `Currency` valid hai.
3. **Currency Match Check**: Handler dono accounts ka balance aur currency check karta hai.
4. **Database Transaction** ([`store.go`](file:///c:/Users/apoor/Desktop/golang/proj/db/sqlc/store.go)):
   - A single SQL transaction starts (`BEGIN`).
   - Ek entry banti hai `-amount` (FromAccount ke liye).
   - Ek entry banti hai `+amount` (ToAccount ke liye).
   - Dono accounts ka balance atomically update hota hai.
   - Transaction commit hota hai (`COMMIT`).
5. **Response**: HTTP `200 OK` ke saath transfer details client ko return hoti hain.
